# 壁画裂隙矩形贴片精确加固

潮湿壁画上的裂隙常呈 **孔洞、细枝和孤岛**。保护员需要用 **不可重叠的矩形纤维贴片**
覆盖全部裂格，且不能压住任何完好格。局部贪心（哪里大贴哪里）常常多耗贴片；
本项目在浏览器内自行实现 **精确状态空间搜索**，给出贴片数最少的唯一可复算方案。

纯前端应用：TypeScript + React + Vite，**无业务后端、无任何外部在线调用**，
所有计算在浏览器本地（搜索在 Web Worker 中执行，不阻塞界面）。

## 业务规则

- 网格大小：`1×1` 至 `12×12`，可点击单元格切换「裂格 / 完好格」，裂格最多 60 个。
- 合法贴片：
  - 边沿格线放置（轴对齐整数矩形）；
  - 贴片内 **只含裂格**，不得压住完好格；
  - 贴片之间 **不得重叠**；
  - 所有贴片的 **并集恰为全部裂格**（不多不少）。
- 优化目标（唯一主目标）：**贴片数量最少**。
- 并列决胜：把每个矩形记为一个基坐标的四元整数
  `[上, 左, 下, 右]`（行、列均 **自 1 起**，含边界），
  各方案内部先按该四元组字典序排序，再把所有矩形依次拼接成整数序列，
  **取字典序最小的方案**。因此对任一合法输入，最终只会呈现唯一一个可复算的加固方案。
  （引擎内部用等价的 0 起索引计算；整体加一常量偏移不改变字典序比较结果。）

## 已安装基线与改造方案

保护员可将当前已求得的加固方案 **标记为「已安装基线」**，随后继续点击网格记录
裂隙 **扩展**（新增裂格）或 **愈合**（取消裂格），并从同一页面 **生成改造方案**；
原有「开始精确搜索」流程保持可用，互不影响。

- 改造求解在当前裂格上形成 **合法的最终矩形覆盖**（规则同上）。
- 与基线坐标 **完全相同** 且仍只覆盖裂格的贴片视为 **保留**（不消耗操作）。
- 目标（依次决胜，结果唯一可复算）：
  1. **拆除数 ＋ 新增数 最少**（主目标）；
  2. **最终贴片总数 最少**；
  3. 最终方案的 **既有坐标字典序**（一基 `[上,左,下,右]` 展平序列）最小。
- SVG 以颜色区分 **保留（绿）/ 新增（蓝）/ 拆除（红虚线）** 三类贴片，
  并列出操作数与每块贴片的可复算一基坐标。
- 状态规则：
  - **编辑裂格** 只清除过期结果（旧解与改造结果），**同尺寸基线保留**；
  - **尺寸改变** 会明确清除不再兼容的基线并说明原因；
  - **基线尚未建立、搜索被截断或尺寸改变** 时不展示改造结果，页面会说明原因；
  - Worker 失败时的 **同步回退** 对改造求解执行完全相同的目标。

## 界面功能

- SVG 网格：点击切换裂格；深色为裂格，彩色圆角块为最终贴片。
- 结果面板：最优贴片数、搜索状态数、耗时、局部贪心对照（贪心多耗几块一目了然）。
- 每块贴片的 `上/左/下/右` 坐标列表。
- **分支取舍回放**：记录搜索中的「采用分支 / 下界剪枝 / 放置后超限回溯 /
  同态记忆剪枝 / 得到完整方案 / 贪心初始上界」等事件，可用按钮或滑块逐步查看，
  图上同步高亮当前候选矩形与锚点格。
- 明确错误反馈：尺寸非整数、超出 1–12、裂格超过 60、越界等情况都会给出原因；
  **任何越界/非法输入都会立即清除旧解**，避免把过期方案当作当前答案。
- **已安装基线**：一键把当前最优方案标记为基线（灰色虚线框提示安装位置）；
  继续编辑裂格后点「生成改造方案」，SVG 分色显示保留/新增/拆除贴片，
  并给出操作数统计与三组可复算坐标清单。
- 内置四个预设：孔洞（3×3 环）、狭枝（十字）、并列决胜（L 形三格的横/竖并列，
  字典序取横铺）、贪心反例（精确最优 2 块、局部贪心 3 块）。

## 搜索算法（完备且可复算）

实现在 `src/lib/solver.ts`：

1. **确定性锚点**：每一步选行优先序下第一个未覆盖裂格。
2. **完备候选枚举**：枚举「锚点列连续自由行带 × 行带内包含锚点列的左右界」
   生成的每一个只含自由裂格的矩形。任何合法铺法中覆盖锚点的那块矩形必在其中，
   因此搜索朴素完备（不依赖“极大矩形不劣”之类的可争辩剪枝）。
3. **初始上界**：先以同一锚点规则跑一遍「每步取面积最大候选」的贪心解。
4. **下界剪枝**：在剩余裂格中构造一个“任意两格都不可能被同一矩形覆盖”的格集
   （两格可同矩形覆盖 ⇔ 其包围盒内当前全为自由裂格），其大小是贴片数的合法下界，
   不弱于四邻接连通分量下界。
5. **同态记忆**：同一剩余覆盖形态若曾以严格更少的贴片数到达，则当前路径必不更优。
6. **字典序决胜**：叶节点比较「一基坐标」展平整数序列（内部 0 起坐标整体 +1，
   常量偏移不改变比较结果），全局保留最小者。

另在 `src/lib/bruteforce.ts` 提供一个 **刻意不同实现** 的独立慢速穷举器
（枚举全部合法子矩形 + MRV 精确覆盖回溯），仅用于验收交叉验证。

## 改造求解（`src/lib/renovation.ts`）

设基线 B 块、最终保留 R 块、新增 A 块，则操作数 = (B − R) + A，
等价于最小化逐块重量和 Σw(r)（保留块 w = −1、新增块 w = +1）。
求解复用主搜索的确定性锚点与完备候选枚举框架，目标替换为
**(重量, 块数, 字典序)** 的三元字典序：

1. **下界剪枝**：剩余至少还需 lb 块贴片（packing 下界），每块重量 ≥ −1，
   且至多还能保留 retainable 块基线 → 追加重量 ≥ lb − 2·retainable。
2. **支配记忆**：同一剩余形态曾以字典序更小的 (重量, 块数) 到达，则当前路径必不更优。
3. 状态数硬上限熔断；截断时标记 `truncated`，界面不展示改造结果。

求解器、Worker 消息契约（`{type:'renovate', …, baseline}` ↔ `{type:'renovate', result}`）
与 React 状态共同传递基线与改造结果；Worker 失败时同步回退执行相同目标。
验收用独立枚举器（`bruteForceRenovation`：枚举全部精确覆盖后逐方案评分）
与主改造求解的实现路径完全不同。

## 本地开发

```bash
npm install
npm run dev        # 开发服务器 http://localhost:5173
npm run build      # 类型检查 + 生产构建（输出到 dist/）
npm run preview    # 本地预览生产构建
```

## 测试

```bash
npm run typecheck  # 仅 TypeScript 类型检查
npm run test       # Vitest：单元测试 + 全部 65536 个 4×4 图样穷举交叉验证
npm run e2e        # Playwright：真实 Chromium 交互测试（自动 build + preview）
npm run verify     # 一键：typecheck + vitest + playwright
```

- **Vitest**（`tests/`）
  - `rect.test.ts`：坐标、排序、字典序、铺法合法性（重叠/压完好格/遗漏/越界）。
  - `validation.test.ts`：全部非法输入类别与错误文案。
  - `solver.test.ts`：孔洞、狭枝、孤岛、并列决胜（L 形横/竖铺法）、
    确定性与插入顺序无关、分支轨迹、12×12/60 裂格性能。
  - `renovation.test.ts`：扩展/愈合/无变化/全部愈合、空基线退化、三级决胜
    （操作数 → 最终块数 → 字典序）、随机图样对与独立枚举器交叉验证、
    确定性与截断标记。
  - `renovation3x3.test.ts`：**独立枚举器核对全部非空旧图样 × 任意新图样的
    3×3 图样对（511 × 512 = 261,632 对）**：操作数、最终方案、保留/拆除/新增
    分类逐坐标一致，并确认扩展、愈合、无变化三类场景均被实际覆盖。
  - `exhaustive4x4.test.ts`：**独立慢速穷举器对全部 2¹⁶ = 65536 个 4×4 图样**
    逐一核对最优贴片数与字典序决胜方案，并断言孔洞类、狭枝（走廊）类与并列类
    图样均被实际覆盖。
- **Playwright**（`e2e/`，真实浏览器）
  - `app.spec.ts`：点击切换裂格与计数、应用 12×12、非法尺寸与非整数的错误反馈及旧解清除、
    60 裂格上限、三个预设的搜索结果、SVG 贴片渲染、分支回放逐步联动、
    同一图样两次搜索结果逐字一致。
  - `renovation.spec.ts`：未建立基线时的反馈与原搜索不受影响、尺寸改变明确清除
    不兼容基线、同尺寸编辑保留基线、**扩展 / 愈合 / 无变化** 三种场景的
    SVG 图层（保留/新增/拆除）与操作清单坐标、Worker 失败时同步回退仍按
    相同目标生成改造方案。

## Docker 发布与验收

```bash
# 发布（默认宿主端口 8080）
docker compose up --build web
# → http://localhost:8080

# 用 WEB_PORT 覆盖宿主端口
WEB_PORT=9000 docker compose up --build web

# 一次性验收服务（类型检查 + Vitest 穷举验收 + Playwright 真实交互，跑完即退出）
docker compose build verify
docker compose run --rm verify
```

- `web`：多阶段构建，最终镜像仅为 nginx + 静态产物（`dist/`），
  宿主端口 `${WEB_PORT:-8080}` 映射到容器 80。
- `verify`：基于 Playwright 官方镜像（浏览器预装）的一次性服务，
  `restart: "no"`，退出码即验收结论。

## 目录结构

```
src/
  lib/
    rect.ts         # 矩形模型、字典序工具、铺法合法性校验
    solver.ts       # 精确状态空间搜索（主算法 + 分支轨迹）
    renovation.ts   # 基线改造求解（拆除+新增最少 → 最终块数 → 字典序）
    bruteforce.ts   # 独立慢速穷举器与改造枚举器（仅验收用）
    validation.ts   # 尺寸/裂格校验与明确错误信息
  workers/
    searchWorker.ts # Web Worker 包装（search / renovate 消息契约）
  App.tsx           # React 界面（SVG 网格、结果、基线与改造、分支回放）
tests/              # Vitest（含 65536 图样穷举与 261,632 图样对改造验收）
e2e/                # Playwright 真实交互测试
docker/             # nginx 配置
Dockerfile          # deps / build / verify / web 多阶段
docker-compose.yml  # web（WEB_PORT 覆盖）+ 一次性 verify
```
